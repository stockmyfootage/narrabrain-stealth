01 / System Foundations & Philosophy

The narrabrain platform serves creators who interface continuous 8-to-12 hour blocks in highly controlled visual spaces (grading suites, mixing bays) interacting with extremely complex, high-density telemetry timelines.

Traditional consumer web guidelines fail in this environment. High screen contrast, luminous light modes, or heavy saturated brand hues cause immediate ocular fatigue, retinal burn-in, and severe chromatic adaptation. Chromatic adaptation shifts an editor’s perception of white balance, leading to flawed color corrections and grading mistakes.

“The UI must be an invisible frame. The canvas stays completely dark and structurally desaturated, ensuring the user's focus is focused entirely on raw master content.”

Core Layout Maxims

  • The 90/10 Asset Ratio: Exactly 90% of active screen configurations must utilize fully desaturated gray scales. Saturated focus accents must occupy 10% or less of real estate, used exclusively to accelerate workflow orientation.
  • Zero Halation Typography: Pure white text fields on dark monitors cause text "haloing" or visual ghosting. narrabrain enforces stepped-down illumination tokens for high-density reading.
  • Structural Contrast via Depth: Panel segments are isolated not through high-contrast colored lines, but by layered, mathematical luminance adjustments (Z-axis elevation mapping).

02 / Color Architecture & Token Schema

The color space configuration is mapped explicitly to combat macular exhaustion. All core variables must be referenced as system design tokens. Direct raw hex mapping inside component modules is structurally banned to preserve framework stability.

--nv-accent-success #24A19C Operational Utility Green. Restricted to system telemetry, render states, and syntax indicators.
--nv-accent-warning #D18E34 Telemetry Warning Orange. Highlights broken rendering paths, pipeline failures, and dissatisfaction telemetry loop inputs.
Architectural Directive // Chromatic Guardrails (Green)

The Rule of Functional Utility Green (--nv-accent-success): To prevent ocular fatigue and protect users from chromatic adaptation during critical post-production tasks, this green must never be used for promotional branding, decorative borders, or primary button elements. It is strictly reserved as an operational metric to indicate 100% completed engine processes, successful asset compilations, and terminal code telemetry.

Architectural Directive // Telemetry Loop Guardrails (Orange)

The Rule of Functional Warning Orange (--nv-accent-warning): This token serves to highlight a failed internal engine layout or compile process. Crucially, it functions as an interactive hook for user dissatisfaction inputs—capturing operational feedback loops specifically utilized for continuous model output training and structural dataset refinement. It must never populate static decorative surfaces.

Micro-Text Readability Parameters

When formatting timecodes, parameter values, or audio track configurations down to sizes smaller than 11px, strict typesetting guidelines must be executed via CSS to bypass the blurring effect typical of dark environments:

  • Letter Tracking Enhancement: All UI metadata labels at smaller sizes must force a letter-spacing index of 0.05em or higher to guarantee spacing between character glyph boundaries.
  • Anti-Aliasing Smoothing: Webkit rendering flags must be hardcoded inside global application frames to eliminate display pixel fragmentation (-webkit-font-smoothing: antialiased;).
